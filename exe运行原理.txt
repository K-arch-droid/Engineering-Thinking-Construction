# ============================================================
#  Python 基础知识速查（阅读本文档前建议先看）
# ============================================================
#
#  1. .exe 是什么？
#     Windows 可执行文件。双击后操作系统会加载它并执行里面的机器码。
#     Python 程序本身不能直接变成 .exe，需要借助 PyInstaller 这样的工具。
#
#  2. Python 解释器是什么？
#     Python 代码需要一个"翻译官"把它翻译成电脑能理解的机器码。
#     这个翻译官就是 Python 解释器（python.exe / python314.dll）。
#     打包时，PyInstaller 会把解释器一起塞进 .exe。
#
#  3. 字节码（.pyc）是什么？
#     Python 源码（.py）先被编译成字节码（.pyc），再由解释器执行。
#     字节码是介于源码和机器码之间的中间格式。
#     PyInstaller 打包时会把 .py 编译成 .pyc，嵌入到 exe 内部。
#
#  4. 动态链接库（.dll）是什么？
#     包含可被多个程序共享的代码和数据。
#     Python 解释器本身就是 python314.dll。
#     打包后它被放在 _internal/ 目录中。
#
#  5. sys 模块是什么？
#     Python 内置模块，提供 Python 解释器的运行时信息。
#     打包后会多出两个重要属性：
#       sys.frozen = True（标记"我是打包后的程序"）
#       sys.executable = exe 文件的完整路径
#
#  6. import 是怎么工作的？
#     import gui → Python 在 sys.path 列出的目录中搜索 gui.py
#     打包后，sys.path 会包含 _internal/ 目录（而不是源码目录）
#     所以 import 能找到嵌入在 exe 内部的 .pyc 文件
#
#  7. mainloop() 是什么？
#     tkinter 的事件循环。程序进入"等待状态"，监听鼠标点击、
#     键盘输入等事件，然后调用对应的回调函数。
#     用户关闭窗口时 mainloop() 才会返回，程序才会结束。
#
# ============================================================


# ============================================================
#  打包后的目录结构 —— 你的程序长什么样
# ============================================================
#
#  在看运行原理之前，先认识打包后的目录结构。
#  这是 PyInstaller --onedir 模式生成的标准布局：
#
#    dist/个人记账本/
#    │
#    ├── 个人记账本.exe          ← 你双击的文件（3.1 MB）
#    │   这是"引导程序"（bootloader），很小，
#    │   它的工作是启动 Python 解释器并执行你的代码。
#    │
#    ├── accounts.json           ← 用户数据（可读可写）
#    │   你的记账记录保存在这里。
#    │   为什么在 exe 旁边而不是 _internal/ 里？
#    │   因为 _internal/ 是只读的（会被冻结），
#    │   accounts.json 需要随时读写，所以放在 exe 旁边。
#    │
#    └── _internal/              ← PyInstaller 的内部目录（只读）
#        │
#        ├── python314.dll       ← Python 解释器（核心）
#        │   这就是 python.exe 的核心部分。
#        │   你的 Python 代码靠它来执行。
#        │
#        ├── base_library.zip    ← Python 标准库（压缩）
#        │   os、sys、json、datetime 等标准模块都在里面。
#        │   PyInstaller 把它们压缩成一个 zip 文件。
#        │
#        ├── ttkbootstrap/       ← 第三方库：GUI 主题
#        │   18 个现代主题的样式文件（.json）。
#        │   通过 --collect-all 参数收集进来的。
#        │
#        ├── PIL/                ← 第三方库：图像处理
#        │   Pillow 库，用于生成图标等。
#        │
#        ├── gui.pyc             ← 你的代码（编译后的字节码）
#        ├── config.pyc          ← 你的代码
#        ├── models.pyc          ← 你的代码
#        ├── storage.pyc         ← 你的代码
#        ├── utils.pyc           ← 你的代码
#        ├── theme.pyc           ← 你的代码
#        └── ui_components.pyc   ← 你的代码
#        │
#        ├── assets/
#        │   └── icon.ico        ← 应用图标
#        │
#        ├── code阅读目录.txt     ← 学习文档
#        ├── UI交互逻辑.txt       ← 学习文档
#        ├── 更新日志.txt         ← 学习文档
#        ├── README.md           ← 项目说明
#        └── docs/               ← 设计文档目录
#
#  关键区别：
#    exe 旁边（可写）→ 用户数据（accounts.json）
#    _internal/（只读）→ 程序代码 + 资源文件
#

# ============================================================
#  启动全过程 —— 从双击到窗口出现
# ============================================================

# ============================================================
#  第一步：你双击了 个人记账本.exe
# ============================================================
#
#  【发生了什么】
#  Windows 操作系统接收到你的双击事件：
#    1. 资源管理器（Explorer）检测到 .exe 文件
#    2. 操作系统创建一个新进程
#    3. 把 exe 文件加载到内存
#    4. 跳转到 exe 的入口点（entry point），开始执行
#
#  【exe 的入口点是什么？】
#  普通的 .exe 文件有一个 main() 函数作为入口。
#  PyInstaller 打包的 .exe 也有一个入口，但它不是你的 main()，
#  而是 PyInstaller 自己的"引导程序"（bootloader）。
#
#  引导程序的工作：
#    1. 设置环境变量（让 Python 知道库在哪里）
#    2. 找到并加载 Python 解释器（python314.dll）
#    3. 初始化 Python 运行时
#    4. 执行你的代码入口（gui.py）
#
#  这就是为什么 exe 文件只有 3.1 MB，但整个文件夹有 43 MB——
#  exe 本身很小，大部分体积在 _internal/ 里的 Python 解释器和库。
#
# ============================================================


# ============================================================
#  第二步：引导程序启动 Python 解释器
# ============================================================
#
#  【引导程序做了什么】
#
#    个人记账本.exe（引导程序）
#        |
#        | ① 设置环境变量
#        |    - PYTHONHOME = _internal/（告诉 Python 标准库在哪）
#        |    - PYTHONPATH = _internal/（告诉 Python 搜索路径）
#        |
#        | ② 加载 Python 解释器
#        |    LoadLibrary("_internal/python314.dll")
#        |    这是 Windows API，把 DLL 加载到进程内存中
#        |
#        | ③ 初始化 Python 运行时
#        |    Py_Initialize() —— Python C API
#        |    此时 Python 解释器开始工作
#        |
#        | ④ 设置 sys.path
#        |    sys.path = ["_internal/", "_internal/base_library.zip"]
#        |    告诉 Python：import 的时候去哪里找模块
#        |
#        | ⑤ 执行入口脚本
#        |    PyRun_SimpleFile("gui.py")
#        |    把 gui.py 的字节码交给 Python 解释器执行
#        |
#        v
#    gui.py 的 main() 开始执行
#
#  【为什么需要引导程序？】
#  .exe 文件本身不能直接运行 Python 代码。
#  Python 代码需要 Python 解释器来执行。
#  引导程序的职责就是"搭桥"——在 .exe 和 Python 之间建立连接。
#
#  这就像翻译官：
#    你（.exe）不会说外语（Python 字节码），
#    翻译官（引导程序）帮你请了一位外语专家（Python 解释器），
#    然后你说的话（代码）就能被理解并执行了。
#
# ============================================================


# ============================================================
#  第三步：gui.py 的 main() 开始执行
# ============================================================
#
#  【Python 解释器开始执行 gui.py】
#
#    gui.py 的入口（代码中的最后几行）：
#
#      if __name__ == "__main__":
#          main()
#
#    __name__ == "__main__" 的含义：
#      当 gui.py 被直接运行时（而不是被 import），
#      __name__ 的值是 "__main__"，此时才执行 main()。
#      这是 Python 的约定：只有直接运行的脚本才执行主逻辑。
#
#    main() 函数只有一行代码：
#      def main():
#          app = AccountApp()
#          app.run()
#
#    接下来会执行 AccountApp.__init__()，这是整个程序的启动流程。
#
# ============================================================


# ============================================================
#  第四步：AccountApp.__init__() 七步启动
# ============================================================
#
#  【启动流程图】
#
#    AccountApp.__init__()
#        |
#        | ① 加载用户设置
#        |    load_settings() → 从 settings.json 读取字体、主题、预设
#        |    路径：exe 旁边的 settings.json（可写）
#        |
#        | ② 创建主窗口
#        |    ttk.Window(title="个人记账本 v1.5", themename="cosmo")
#        |    设置窗口标题、主题、尺寸、最小尺寸
#        |
#        | ③ 注入全局样式
#        |    apply_theme(self.style) → 更新字体、颜色
#        |
#        | ④ 应用保存的预设（如果有）
#        |    if saved_preset: apply_preset(saved_preset)
#        |    让深色/护眼模式在启动时立即生效
#        |
#        | ⑤ 创建存储管理器
#        |    self.storage = Storage()
#        |    确保 accounts.json 存在（不存在则创建空文件）
#        |
#        | ⑥ 初始化缓冲数据
#        |    self._entries = []        # 内存工作副本
#        |    self._undo_stack = []     # 撤回栈
#        |    self._has_changes = False # 未保存标记
#        |
#        | ⑦ 注册窗口关闭事件
#        |    self.root.protocol("WM_DELETE_WINDOW", self._on_close)
#        |    拦截关闭按钮，弹出保存确认
#        |
#        v
#    AccountApp.__init__() 完成，回到 main()
#
# ============================================================


# ============================================================
#  第五步：app.run() 启动事件循环
# ============================================================
#
#  【run() 方法做了什么】
#
#    def run(self):
#        self._entries = self.storage.load_all()  # ① 加载数据
#        self._refresh_list()                      # ② 刷新界面
#        self.root.mainloop()                      # ③ 进入事件循环
#
#  ① storage.load_all()：
#    从 accounts.json 加载所有记账记录到内存工作副本。
#    这是用户之前保存的数据。
#
#  ② _refresh_list()：
#    把内存中的数据显示到界面上（填充收支流水表格）。
#
#  ③ mainloop()：
#    tkinter 的事件循环。程序进入"等待状态"：
#      - 监听鼠标点击（按钮、表格行、菜单）
#      - 监听键盘输入（文本框、快捷键）
#      - 监听窗口事件（关闭、最小化、调整大小）
#    每当检测到事件，就调用对应的回调函数。
#    用户关闭窗口时 mainloop() 才会返回。
#
#  【此时程序已经完全启动】
#  用户看到的是：
#    - 窗口标题："个人记账本 v1.5"
#    - 4 个标签页：记一笔 / 收支流水 / 月度统计 / 设置
#    - 顶部菜单栏：帮助
#    - 如果有历史数据，收支流水表格已经填充好了
#
# ============================================================


# ============================================================
#  第六步：路径解析 —— 程序怎么找到文件
# ============================================================
#
#  【这是打包后最容易出问题的地方】
#
#  开发时（python gui.py）：
#    __file__ = "C:/项目/config.py"
#    所有文件都在同一个目录，路径很简单。
#
#  打包后（个人记账本.exe）：
#    __file__ 不存在了！代码嵌入在 exe 内部。
#    程序需要"猜"文件在哪里。
#
#  【config.py 的解决方案】
#
#    两个路径函数，分别处理两种文件：
#
#    get_base_path() → 用户数据目录
#      判断逻辑：
#        if sys.frozen == True:    # 打包后
#            return exe 所在目录    # 可写，存放 accounts.json
#        else:                     # 开发时
#            return 源码所在目录    # __file__ 的目录
#
#    get_resource_path() → 内部资源目录
#      判断逻辑：
#        if sys.frozen == True:    # 打包后
#            return exe 所在目录 + "/_internal"  # 只读资源
#        else:                     # 开发时
#            return 源码所在目录    # 和 __file__ 同目录
#
#  【为什么需要两个路径？】
#
#    用户数据（accounts.json）：
#      - 需要随时读写（记账、删除、修改）
#      - 必须在可写位置（exe 旁边）
#      - 每个用户的记账数据不同
#
#    内置资源（文档、图标）：
#      - 只读，程序运行期间不会修改
#      - 可以在只读位置（_internal/ 内部）
#      - 所有用户的资源文件相同
#
#  【实际路径映射】
#
#    开发时：
#      DATA_DIR         = "C:/项目/"
#      DATA_FILE        = "C:/项目/accounts.json"
#      get_resource_path("code阅读目录.txt") = "C:/项目/code阅读目录.txt"
#
#    打包后：
#      DATA_DIR         = "dist/个人记账本/"
#      DATA_FILE        = "dist/个人记账本/accounts.json"
#      get_resource_path("code阅读目录.txt") = "dist/个人记账本/_internal/code阅读目录.txt"
#
#  【如果路径出错了会怎样？】
#    - accounts.json 找不到 → 程序创建空文件（Storage._ensure_file）
#    - 资源文件找不到 → 菜单点击时弹出"文件不存在"错误
#    - _internal/ 目录不存在 → 打包配置有误，需要检查 --add-data
#
# ============================================================


# ============================================================
#  第七步：菜单栏 —— 打开学习文档
# ============================================================
#
#  【菜单栏怎么加载的】
#
#  AccountApp.__init__() → _build_ui() → _build_menubar()
#
#  _build_menubar() 创建菜单栏：
#    menubar = tk.Menu(self.root)          # 顶级菜单栏
#    help_menu = tk.Menu(menubar, tearoff=0)  # 下拉菜单
#    help_menu.add_command(label="📖 代码阅读目录", command=...)
#    menubar.add_cascade(label="帮助", menu=help_menu)
#    self.root.config(menu=menubar)
#
#  【用户点击"📖 代码阅读目录"后发生了什么】
#
#    用户点击菜单
#        |
#        v
#    tkinter 触发 command 回调
#        |
#        v
#    _open_doc_code_guide()
#        |
#        v
#    _open_file("code阅读目录.txt")
#        |
#        v
#    get_resource_path("code阅读目录.txt")
#        |
#        ├── 开发时 → "C:/项目/code阅读目录.txt"
#        └── 打包后 → "dist/个人记账本/_internal/code阅读目录.txt"
#        |
#        v
#    检查文件是否存在
#        |
#        ├── 存在 → os.startfile(filepath) → 用记事本打开
#        └── 不存在 → show_error("文件不存在") → 弹出错误提示
#
#  【跨平台打开文件】
#
#    os.startfile(filepath)：
#      Windows 内置函数，用默认程序打开文件。
#      .txt → 记事本，.md → 默认 Markdown 编辑器
#      传目录路径 → 资源管理器打开文件夹
#
#    subprocess.Popen(["open", filepath])：
#      macOS 的打开方式，"open" 是系统命令。
#
#    subprocess.Popen(["xdg-open", filepath])：
#      Linux 的打开方式，xdg-open 是 FreeDesktop 标准。
#
#    sys.platform 的值：
#      "win32"  = Windows
#      "darwin" = macOS
#      "linux"  = Linux
#
# ============================================================


# ============================================================
#  第八步：数据读写 —— accounts.json 的生命周期
# ============================================================
#
#  【程序启动时】
#    storage.load_all() → 从 accounts.json 加载数据到内存
#
#  【用户记账时】
#    _on_save_entry() → 追加到内存工作副本（不写盘）
#    标记 _has_changes = True
#
#  【用户删除时】
#    _on_delete_entry() → 从内存工作副本移除（不写盘）
#    被删除的记录压入 _undo_stack（支持撤回）
#
#  【用户关闭窗口时】
#    _on_close() → 弹出确认对话框
#      ├── "保存" → storage.save_all() → 写入 accounts.json
#      ├── "不保存" → 丢弃改动，直接关闭
#      └── "取消" → 返回程序继续操作
#
#  【为什么用缓冲保存？】
#    如果每记一笔账都立即写盘：
#      - 频繁的磁盘 I/O 会拖慢界面
#      - 写到一半断电会损坏文件
#    缓冲保存：先在内存中操作，关闭时统一写盘。
#    好处：快、安全、支持撤回。
#
#  【accounts.json 在哪里？】
#    打包后在 exe 旁边（不是 _internal/ 里）。
#    因为 _internal/ 是只读的，accounts.json 需要随时读写。
#    config.py 的 get_base_path() 负责返回正确的路径。
#
# ============================================================


# ============================================================
#  第九步：主题和预设 —— 界面怎么变成深色的
# ============================================================
#
#  【启动时的主题加载】
#
#    __init__() 中：
#      settings = load_settings()  # 读取 settings.json
#      saved_preset = settings.get("preset", "")
#
#      if saved_preset in THEME_PRESETS:
#          apply_preset(saved_preset)  # 应用预设颜色到 ttk 组件
#
#    run() 中：
#      if saved_preset in THEME_PRESETS:
#          apply_preset_to_root(self.root, saved_preset)  # 应用到 tk 原生组件
#
#  【为什么分两步？】
#    ttkbootstrap 的组件（TButton、TEntry 等）和 tkinter 原生组件（Menu、Text）
#    使用不同的样式系统：
#      - apply_preset() 修改 ttkbootstrap 的 Style
#      - apply_preset_to_root() 递归遍历窗口，修改 tk 原生组件的颜色
#
#  【settings.json 在哪里？】
#    在 exe 旁边（和 accounts.json 同目录）。
#    这也是用户数据，需要可写。
#
# ============================================================


# ============================================================
#  第十步：程序退出 —— 关闭时发生了什么
# ============================================================
#
#  【用户点击窗口的 ✕ 按钮】
#
#    Windows 发送 WM_DELETE_WINDOW 消息
#        |
#        v
#    tkinter 触发 _on_close() 回调
#        |
#        v
#    _on_close() 检查 self._has_changes
#        |
#        ├── 没有改动 → root.destroy() → 程序退出
#        │
#        └── 有未保存的改动 → 弹出确认对话框
#              ├── "保存" → storage.save_all() → root.destroy()
#              ├── "不保存" → root.destroy()（丢弃改动）
#              └── "取消" → 返回程序继续操作
#
#  【root.destroy() 做了什么】
#    1. 销毁所有 tkinter 组件（窗口、按钮、表格等）
#    2. mainloop() 返回
#    3. run() 函数返回
#    4. main() 函数返回
#    5. Python 解释器开始清理
#       - 调用所有对象的 __del__ 方法
#       - 释放内存
#       - 关闭打开的文件
#    6. Python 解释器关闭（Py_Finalize()）
#    7. 引导程序退出
#    8. 操作系统回收进程资源
#    9. 程序从任务栏消失
#

# ============================================================
#  常见问题排查
# ============================================================
#
#  Q1: 双击 exe 没反应 / 闪退
#  A1: 可能原因：
#      - 缺少 Visual C++ 运行时（安装 VC++ Redistributable）
#      - 杀毒软件拦截（添加白名单）
#      - 路径包含中文或特殊字符（把文件夹移到纯英文路径）
#      - 用命令行运行看报错：cmd → cd 到目录 → 个人记账本.exe
#
#  Q2: 提示"文件不存在"
#  A2: 资源文件没有被打包进去：
#      - 检查 build.py 的 DATAS 列表是否包含该文件
#      - 重新运行 python build.py 打包
#      - 检查 _internal/ 目录里有没有该文件
#
#  Q3: accounts.json 数据丢失
#  A3: accounts.json 在 exe 旁边（不是 _internal/ 里）：
#      - 如果你移动了 exe，accounts.json 不会跟着移动
#      - 建议把整个 dist/个人记账本/ 文件夹一起移动
#      - 或者把 accounts.json 备份到安全位置
#
#  Q4: 打包后程序启动很慢
#  A4: --onedir 模式已经比 --onefile 快很多了。
#      如果还是很慢：
#      - 检查是否有杀毒软件在扫描（添加白名单）
#      - 第一次启动会慢一些（Windows 需要建立文件缓存）
#
#  Q5: 打包后中文路径/文件名乱码
#  A5: PyInstaller 对中文路径的支持有限：
#      - 建议把项目放在纯英文路径下打包
#      - 或者在打包后的 dist 目录中手动重命名
#
#  Q6: 打包后程序体积很大（43 MB）
#  A6: 这是正常的。体积分布：
#      - python314.dll ≈ 5 MB（Python 解释器）
#      - base_library.zip ≈ 10 MB（标准库）
#      - ttkbootstrap ≈ 5 MB（GUI 主题库）
#      - 其他依赖 ≈ 20 MB
#      - 你的代码 < 1 MB
#      如果需要减小体积，可以用 --onefile 或排除不需要的模块。
#

# ============================================================
#  工程思维要点速查
# ============================================================
#
#  1. 引导程序      exe 不是直接运行 Python，而是通过 bootloader 桥接
#  2. 解释器嵌入    python314.dll 被打包到 _internal/，不依赖系统 Python
#  3. 字节码编译    .py → .pyc，打包时编译一次，运行时直接加载
#  4. 路径分离      用户数据（可写）放 exe 旁边，内置资源（只读）放 _internal/
#  5. 冻结检测      sys.frozen = True 标记打包状态，代码据此选择路径
#  6. 环境变量      PYTHONHOME / PYTHONPATH 告诉解释器去哪里找库
#  7. 事件循环      mainloop() 是 GUI 程序的核心——等待事件、处理事件
#  8. 缓冲保存      先改内存，关闭时写盘——快、安全、支持撤回
#  9. 跨平台打开    os.startfile (Win) / open (Mac) / xdg-open (Linux)
# 10. 优雅退出      检测未保存改动 → 确认对话框 → 保存或丢弃 → 清理资源
#
