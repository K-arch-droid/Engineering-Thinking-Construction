# ============================================================
#  第一类：GitHub 相关（代码托管平台需要的文件）
# ============================================================
#
#  GitHub 是一个代码托管平台，你可以把代码上传上去，
#  别人可以下载、查看、提建议。就像"代码的网盘"。
#
#  以下文件是 GitHub 需要的，没有它们 GitHub 上的展示会不完整。
#
# ------------------------------------------------------------
#  .gitignore
# ------------------------------------------------------------
#  作用：告诉 Git（版本管理工具）哪些文件不要上传到 GitHub。
#
#  为什么需要它？
#    有些文件很大（dist/ 有 43MB），上传很慢也没意义。
#    有些文件是自动生成的（__pycache__/），别人不需要。
#    有些文件是隐私的（你的记账数据 accounts.json）。
#
#  它里面写了什么？
#    __pycache__/    ← Python 编译缓存，自动生成的
#    *.pyc           ← 编译后的字节码文件
#    .claude/        ← Claude Code 的配置目录
#
#  没有它会怎样？
#    Git 会把所有文件都上传，包括：
#    - 43MB 的打包产物（上传慢、占用空间）
#    - 你的个人记账数据（隐私泄露！）
#    - 各种临时文件（没必要）
#
#  能删吗？
#    不能。删了会导致不该上传的文件被上传到 GitHub。
#
# ------------------------------------------------------------
#  README.md
# ------------------------------------------------------------
#  作用：项目的"说明书"，别人打开你的 GitHub 仓库第一眼看到的。
#
#  为什么需要它？
#    GitHub 会自动把 README.md 的内容显示在仓库首页。
#    没有它，别人打开你的仓库只看到一堆文件名，不知道这是什么项目。
#
#  它里面写了什么？
#    - 项目名称和简介
#    - 核心功能列表
#    - 运行方式（怎么安装、怎么启动）
#    - 工程架构图（6 层分层设计）
#    - 文件结构说明
#    - 学习资源链接
#
#  没有它会怎样？
#    GitHub 仓库首页会显示一片空白或只有文件列表。
#    别人不知道这个项目是干什么的、怎么用。
#
#  能删吗？
#    不建议。删了项目在 GitHub 上就没有介绍了。
#

# ============================================================
#  第二类：Python 源代码（程序的核心逻辑）
# ============================================================
#
#  这 8 个 .py 文件就是你的程序本身。
#  它们加起来构成了"个人记账本"的全部功能。
#
#  它们之间的关系（从上到下 = 从用户界面到底层逻辑）：
#
#    gui.py          ← 用户看到的界面（最顶层）
#    ui_components.py ← 界面中可复用的小组件
#    theme.py        ← 界面的颜色、字体、主题
#    main.py         ← 命令行版本的入口（备用）
#    storage.py      ← 数据的读写（和硬盘打交道）
#    models.py       ← 数据的结构和校验规则
#    utils.py        ← 通用小工具（日期、金额校验）
#    config.py       ← 全局配置（所有模块共用的常量）
#
# ------------------------------------------------------------
#  gui.py（约 1207 行）—— 界面层
# ------------------------------------------------------------
#  作用：程序的主入口。你双击 exe 后，就是这个文件在运行。
#
#  它负责什么？
#    - 创建窗口、标签页、按钮、表格、菜单栏
#    - 响应用户操作（记账、删除、查询、设置）
#    - 协调其他模块完成业务逻辑
#
#  打个比方：
#    gui.py 就像餐厅的服务员——
#    接待你（显示界面）、记录你的需求（读取输入）、
#    把需求告诉后厨（调用其他模块）、把菜端给你（显示结果）。
#    它自己不做菜（不做业务计算），只负责传话。
#
#  没有它会怎样？
#    程序无法启动。没有界面，用户无法操作。
#    （CLI 版本的 main.py 还能用，但没有图形界面）
#
#  能删吗？
#    不能。删了 GUI 版本就完全不能用了。
#
# ------------------------------------------------------------
#  ui_components.py（约 255 行）—— 组件层
# ------------------------------------------------------------
#  作用：界面中可重复使用的小部件（组件）。
#
#  它负责什么？
#    - FormRow：表单的一行（标签 + 输入框/下拉框）
#    - DataTable：数据表格（显示记账记录的表格）
#    - StatsCard：统计卡片（显示"总收入""总支出"的卡片）
#    - show_confirm / show_info / show_error：弹窗工具
#
#  打个比方：
#    如果 gui.py 是餐厅服务员，那 ui_components.py 就是——
#    餐厅里的标准化餐具。每个服务员都用同样的盘子、碗、筷子，
#    不用每次都从头做一套。这就是"组件复用"。
#
#  没有它会怎样？
#    gui.py 需要把所有界面代码都写在自己身上，变得非常长。
#    而且同样的表格、表单在多个标签页中出现时，代码会重复。
#
#  能删吗？
#    不能。删了 gui.py 会报错（它 import 了这个文件）。
#
# ------------------------------------------------------------
#  theme.py（约 337 行）—— 样式层
# ------------------------------------------------------------
#  作用：控制界面"长什么样"——颜色、字体、主题、预设。
#
#  它负责什么？
#    - 窗口标题、尺寸
#    - 字体配置（字号、字体族）
#    - 颜色常量（成功绿、危险红、主题蓝）
#    - 主题分组（红色系、蓝色系、暗色系等）
#    - 主题预设（深色模式、护眼模式、海洋蓝）
#    - 设置持久化（保存到 settings.json）
#
#  打个比方：
#    theme.py 就像餐厅的装修方案——
#    墙刷什么颜色、灯用什么亮度、桌椅什么风格。
#    你可以在设置页面换"装修风格"（主题），它会立即生效。
#
#  没有它会怎样？
#    界面会变成 tkinter 的默认灰色丑界面。
#    没有主题切换、没有预设、没有字体设置。
#
#  能删吗？
#    不能。删了 gui.py 会报错，界面也没有样式。
#
# ------------------------------------------------------------
#  main.py（约 400 行）—— CLI 入口
# ------------------------------------------------------------
#  作用：命令行版本的入口（不用鼠标，纯键盘操作）。
#
#  它负责什么？
#    - 显示文字菜单（1.记一笔 2.查流水 3.统计 ...）
#    - 读取键盘输入
#    - 调用底层模块完成操作
#
#  打个比方：
#    main.py 是 gui.py 的"文字版"——
#    同样的功能，但不用图形界面，用命令行交互。
#    就像同一家餐厅的"外卖菜单"（文字版）和"堂食菜单"（图文版）。
#
#  没有它会怎样？
#    命令行版本不能用，但 GUI 版本不受影响。
#    对于只想用图形界面的用户，没有影响。
#
#  能删吗？
#    可以，但不建议。它是学习"同一套底层代码服务不同界面"的好例子。
#
# ------------------------------------------------------------
#  storage.py（约 241 行）—— 持久化层
# ------------------------------------------------------------
#  作用：负责数据的读写——把数据存到硬盘、从硬盘读出来。
#
#  它负责什么？
#    - load_all()：从 accounts.json 加载所有记账记录
#    - save_all()：把记账记录写入 accounts.json
#    - 原子写入：先写临时文件，再替换，防止断电丢数据
#    - 备份：删除数据前先备份
#
#  打个比方：
#    storage.py 就像仓库管理员——
#    你要存东西（记账），它帮你放进仓库（写文件）；
#    你要取东西（查账），它帮你从仓库拿出来（读文件）。
#    它还很细心：存东西时先放临时区，确认没问题再正式入库。
#
#  没有它会怎样？
#    程序能启动，但数据无法保存。
#    关了程序再打开，所有记账记录都没了。
#
#  能删吗？
#    不能。删了程序无法读写数据，记账功能完全失效。
#
# ------------------------------------------------------------
#  models.py（约 178 行）—— 模型层
# ------------------------------------------------------------
#  作用：定义"一条记账记录长什么样"以及"什么样的数据是合法的"。
#
#  它负责什么？
#    - BillEntry 类：定义一条记账记录的结构
#      （编号、日期、类型、分类、金额、备注）
#    - validate()：校验数据是否合法
#      （日期格式对不对？金额是不是正数？分类是不是有效的？）
#    - to_dict() / from_dict()：对象和字典的互相转换
#      （存到 JSON 时转成字典，从 JSON 读出来时转回对象）
#
#  打个比方：
#    models.py 就像表格模板——
#    告诉你一张发票必须有：日期、金额、用途。
#    如果日期写成了"abc"，它会说"这不对，日期格式错了"。
#
#  没有它会怎样？
#    程序不知道一条记录应该包含哪些字段。
#    无法校验用户输入是否合法（可能记下金额为"abc"的账）。
#
#  能删吗？
#    不能。删了 gui.py、storage.py、main.py 都会报错。
#
# ------------------------------------------------------------
#  utils.py（约 171 行）—— 工具层
# ------------------------------------------------------------
#  作用：通用小工具函数，各个模块都可能用到。
#
#  它负责什么？
#    - get_today()：获取今天的日期
#    - validate_amount()：校验金额格式（正则表达式）
#    - format_amount()：格式化金额显示
#    - get_month_range()：获取某月的起止日期
#    - safe_input()：安全读取用户输入（CLI 版本用）
#
#  打个比方：
#    utils.py 就像工具箱——
#    里面有锤子、螺丝刀、扳手。
#    谁需要拧螺丝就来借扳手，不用每人自己造一把。
#
#  没有它会怎样？
#    每个模块需要日期、金额校验等功能时，得自己写一遍。
#    代码会重复，改一个地方要改好几个文件。
#
#  能删吗？
#    不能。删了 gui.py、main.py、models.py 都会报错。
#
# ------------------------------------------------------------
#  config.py（约 144 行）—— 配置层
# ------------------------------------------------------------
#  作用：全局配置的"参数表"，所有模块共用的常量都在这里。
#
#  它负责什么？
#    - 数据文件路径（accounts.json 在哪）
#    - 收支类型常量（income / expense）
#    - 分类列表（餐饮、交通、购物...）
#    - 日期格式（%Y-%m-%d）
#    - 金额精度（保留 2 位小数）
#    - PyInstaller 路径兼容（get_base_path / get_resource_path）
#
#  打个比方：
#    config.py 就像餐厅的"标准操作手册"——
#    菜单上有哪些菜（分类列表）、
#    菜价精确到角还是分（金额精度）、
#    发票日期写什么格式（日期格式）。
#    所有服务员（模块）都按这个手册来，保持一致。
#
#  没有它会怎样？
#    每个模块自己定义日期格式、分类列表，容易不一致。
#    改一个日期格式要改 5 个文件，漏一个就出 bug。
#
#  能删吗？
#    不能。删了所有模块都会报错（它们都 import config）。
#

# ============================================================
#  第三类：打包相关（把程序变成 .exe 用的）
# ============================================================
#
#  Python 程序需要 Python 解释器才能运行。
#  "打包"就是把程序 + 解释器 + 依赖 + 资源塞进一个文件夹，
#  让别人的电脑不需要装 Python 就能直接双击运行。
#
#  以下 3 个文件只在打包时用到，正常运行程序不需要它们。
#
# ------------------------------------------------------------
#  build.py（约 232 行）
# ------------------------------------------------------------
#  作用：打包脚本。运行 python build.py 就能自动打包。
#
#  它负责什么？
#    - 调用 PyInstaller 打包工具
#    - 指定入口文件（gui.py）
#    - 配置打包参数（图标、版本信息、数据文件）
#    - 打包完成后复制 accounts.json 到输出目录
#
#  打个比方：
#    build.py 就像"装箱清单"——
#    告诉打包工人（PyInstaller）：
#    "把 gui.py 放进去、把图标放进去、把文档放进去、
#     不要显示控制台窗口、用文件夹模式打包..."
#
#  没有它会怎样？
#    你需要手动在命令行输入很长的 PyInstaller 命令。
#    每次打包都要重新输入，容易打错。
#    有了 build.py，只需 python build.py 一行命令。
#
#  能删吗？
#    可以。不影响程序运行，只是打包时不方便。
#    删了可以手动输入 PyInstaller 命令来打包。
#
# ------------------------------------------------------------
#  version_info.txt（约 32 行）
# ------------------------------------------------------------
#  作用：Windows exe 文件的"身份信息"。
#
#  它负责什么？
#    - 产品名称：个人记账本
#    - 版本号：1.4.0.0
#    - 版权信息：Copyright (C) 2026
#    - 文件描述：个人记账本 - 收支管理工具
#
#  怎么看到这些信息？
#    右键 exe 文件 → 属性 → 详细信息
#    你会看到产品名称、版本号、版权等信息。
#
#  打个比方：
#    version_info.txt 就像产品的"铭牌"——
#    你买了一台冰箱，背面贴着：品牌、型号、生产日期。
#    exe 文件也需要这样的"铭牌"，让别人知道这是什么软件。
#
#  没有它会怎样？
#    exe 文件没有版本信息。
#    右键 → 属性 → 详细信息 里面是空的。
#    程序功能不受影响，只是显得不专业。
#
#  能删吗？
#    可以。不影响程序运行，只是 exe 没有版本信息。
#
# ------------------------------------------------------------
#  assets/icon.ico（约 5 KB）
# ------------------------------------------------------------
#  作用：应用程序的图标。
#
#  它负责什么？
#    - exe 文件在资源管理器中显示的图标
#    - 包含 4 种尺寸：16x16、32x32、48x48、256x256
#    - 16/32/48 用于小图标（文件列表、任务栏）
#    - 256 用于大图标（桌面快捷方式、详细信息视图）
#
#  打个比方：
#    icon.ico 就像 App 的图标——
#    微信有绿色对话框图标、支付宝有蓝色图标。
#    你的记账本有绿色背景 + ¥ 符号的图标。
#
#  没有它会怎样？
#    exe 文件会显示 Windows 默认的空白 exe 图标。
#    在桌面上不容易辨认是哪个程序。
#    程序功能不受影响。
#
#  能删吗？
#    可以。不影响程序运行，只是 exe 没有自定义图标。
#
#  assets/ 目录说明：
#    这个目录专门存放"资源文件"（图标、图片等）。
#    目前只有 icon.ico，以后可以放更多资源。
#

# ============================================================
#  第四类：学习文档（帮你理解代码的）
# ============================================================
#
#  这 4 个 .txt 文件不是程序的一部分，而是"学习材料"。
#  它们帮助你理解代码是怎么写的、为什么这样写。
#  程序运行时不需要它们，但在打包后可以通过菜单栏打开。
#
# ------------------------------------------------------------
#  code阅读目录.txt（约 440 行）
# ------------------------------------------------------------
#  作用：代码阅读指南，告诉你"按什么顺序看代码"。
#
#  它负责什么？
#    - 把所有 .py 文件按数据流排序（从底层到顶层）
#    - 每个文件标注：看哪几行、为什么看、看完能回答什么问题
#    - 包含全景图、核心数据流、工程思维要点速查
#
#  打个比方：
#    它就像博物馆的"参观路线图"——
#    告诉你先看哪馆、再看哪馆、每个馆重点看什么。
#    没有它你也能逛，但可能会迷路或错过重点。
#
#  没有它会怎样？
#    你面对一堆 .py 文件不知道从哪里开始看。
#    可能先看了最复杂的 gui.py，结果看不懂。
#
#  能删吗？
#    可以。不影响程序运行，只是学习时没有指引。
#
# ------------------------------------------------------------
#  UI交互逻辑.txt（约 1936 行）
# ------------------------------------------------------------
#  作用：从"用户操作"角度详解每个按钮背后的代码。
#
#  它负责什么？
#    - 你点了"保存"按钮，代码怎么执行？
#    - 你选了"深色模式"，界面怎么变色？
#    - 你关闭窗口，数据怎么保存？
#    - 每个函数都附带完整源码和逐行注释
#
#  打个比方：
#    它就像电器的"使用说明书 + 电路图"——
#    不仅告诉你"按这个按钮会怎样"，
#    还告诉你"按下去后里面的电路是怎么工作的"。
#
#  没有它会怎样？
#    你知道"点了保存会记账"，但不知道代码是怎么实现的。
#    想修改功能时不知道该改哪个文件的哪一行。
#
#  能删吗？
#    可以。不影响程序运行，只是学习时没有详解。
#
# ------------------------------------------------------------
#  exe运行原理.txt（约 400 行）
# ------------------------------------------------------------
#  作用：从"双击 exe"的角度讲解程序是怎么启动的。
#
#  它负责什么？
#    - 双击 exe 后发生了什么？
#    - PyInstaller 引导程序怎么启动 Python？
#    - 程序怎么找到 accounts.json 和文档？
#    - 包含完整的启动时序图和故障排查指南
#
#  打个比方：
#    它就像汽车的"发动机原理图"——
#    你不需要知道发动机怎么工作也能开车，
#    但如果车坏了，懂原理的人更容易找到问题。
#
#  没有它会怎样？
#    你不知道打包后的程序是怎么跑起来的。

#  第六类：依赖配置（告诉别人要装什么库）

# ------------------------------------------------------------
#  requirements.txt
# ------------------------------------------------------------
#  作用：列出程序需要的第三方库（依赖清单）。

#  它负责什么？
#    - 告诉用户：运行这个程序需要安装哪些库

#
#  打个比方：

#  没有它会怎样？
#    用户不知道需要安装什么库，得自己看代码猜。
#    可能漏装某个库，运行时报错。
#
#  能删吗？
#    可以，但不方便。用户需要手动查看代码来确定依赖。

# ============================================================
#  第八类：自动生成 / 可删除
# ============================================================
#
#  以下文件和目录都是"副产品"——
#  运行程序或打包时自动生成的，删了也没关系。
#
# ------------------------------------------------------------
#  __pycache__/ 目录
# ------------------------------------------------------------
#  作用：Python 的编译缓存。
#
#  它是怎么来的？
#    当你运行 python gui.py 时，Python 会把 .py 编译成 .pyc，
#    缓存在 __pycache__/ 目录中。下次运行时直接加载 .pyc，
#    跳过编译步骤，启动更快。
#
#  没有它会怎样？
#    下次运行时 Python 会重新编译，稍微慢一点（几毫秒）。
#    不影响任何功能。
#
#  能删吗？
#    能。随时可以删，Python 会自动重新生成。
#    .gitignore 已经排除了它，不会上传到 GitHub。
#
# ------------------------------------------------------------
#  build/ 目录
# ------------------------------------------------------------
#  作用：PyInstaller 打包时的临时文件。
#
#  它是怎么来的？
#    运行 python build.py 时，PyInstaller 在这里存放：
#    - 分析结果（依赖关系图）
#    - 编译后的字节码
#    - 临时的 .exe 文件
#
#  没有它会怎样？
#    下次打包时 PyInstaller 会重新生成。
#    不影响任何功能。
#
#  能删吗？
#    能。打包完成后可以删掉节省空间。
#
# ------------------------------------------------------------
#  dist/ 目录
# ------------------------------------------------------------
#  作用：PyInstaller 打包的输出目录（成品）。
#
#  它是怎么来的？
#    运行 python build.py 后，打包好的程序在这里：
#    dist/个人记账本/个人记账本.exe
#
#  没有它会怎样？
#    需要重新运行 python build.py 打包。
#
#  能删吗？
#    能。需要时重新打包即可。
#    但如果你想分发 .exe 给别人，不要删。
#
# ------------------------------------------------------------
#  *.spec 文件（个人记账本.spec）
# ------------------------------------------------------------
#  作用：PyInstaller 自动生成的打包配置文件。
#
#  它是怎么来的？
#    运行 python build.py 时，PyInstaller 自动生成。
#    记录了所有打包参数（入口文件、图标、数据文件等）。
#
#  没有它会怎样？
#    下次打包时 PyInstaller 会重新生成。
#
#  能删吗？
#    能。我们的 build.py 已经包含了所有打包参数，
#    不需要这个 .spec 文件。
#
# ------------------------------------------------------------
#  *.zip 文件（个人记账本_v1.5_Windows.zip）
# ------------------------------------------------------------
#  作用：打包产物的压缩文件（用于分发）。
#
#  它是怎么来的？
#    为了上传到 GitHub Release 而创建的压缩包。
#    把 dist/个人记账本/ 目录压缩成一个 .zip 文件。
#
#  没有它会怎样？
#    需要重新压缩 dist 目录。
#
#  能删吗？
#    能。需要时重新压缩即可。
#
# ============================================================

#  有些目录以 "." 开头，在文件管理器中默认隐藏。

# ------------------------------------------------------------
#  .git/ 目录
# ------------------------------------------------------------
#  作用：Git 版本管理的数据库。
#
#  它负责什么？
#    - 记录所有文件的历史版本（每次改了什么、谁改的）
#    - 支持回退到任意历史版本
#    - 支持多人协作（分支、合并）
#
#  打个比方：

#  没有它会怎样？
#    失去所有版本历史。
#    不能用 git log 查看提交记录。
#    不能用 git diff 对比不同版本。
#    不能推送到 GitHub。
#
#  能删吗？
#    技术上能，但会丢失所有版本历史！
#    如果代码已经推送到 GitHub，远程还有备份。

#  ⚠️ 警告：
#    除非你确定知道自己在做什么，否则不要动这个目录。

#

#    └── import models.py（数据类型）

#    └── import config.py（常量）
#
#  utils.py
#    └── import config.py（格式常量）
