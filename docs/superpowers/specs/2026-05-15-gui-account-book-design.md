# 个人记账本 GUI 版设计文档

> 日期: 2026-05-15
> 状态: 已确认

## 目标

将现有命令行记账本改造为独立窗口桌面应用，支持 UI 风格和字体的后续定制。

## 技术选型

- GUI 框架: tkinter + ttkbootstrap
- 主题库: ttkbootstrap（提供现代主题 + 样式定制能力）
- 依赖: Python 3.10+，pip install ttkbootstrap

## 架构

新增 3 个文件，原有 5 个文件保持不变：

```
├── config.py           # 全局配置（不变）
├── models.py           # 数据模型（不变）
├── storage.py          # 数据持久化（不变）
├── utils.py            # 工具函数（不变）
├── main.py             # CLI 入口（保留）
├── gui.py              # GUI 入口（新建）
├── ui_components.py    # 可复用 UI 组件（新建）
├── theme.py            # 样式/字体配置（新建）
├── requirements.txt    # 加 ttkbootstrap
└── README.md           # 更新
```

### 新文件职责

| 文件 | 职责 |
|------|------|
| `gui.py` | 创建主窗口、加载标签页、启动主循环、协调 UI 事件与业务逻辑 |
| `ui_components.py` | 可复用 UI 组件：表单组件、数据表格、统计卡片、确认对话框 |
| `theme.py` | 集中管理所有视觉参数：字体族、字号、颜色、间距、ttkbootstrap 主题名 |

### 数据流

```
用户操作 GUI → gui.py 接收事件
  → models.py 校验数据
  → storage.py 读写磁盘
  → gui.py 刷新界面显示
```

原有 CLI 数据流不受影响，两个入口共享同一套 models/storage/utils。

### 标签页详细设计

#### 1. 记一笔

录入收支的核心表单页。

组件:
- 日期输入框（默认今天，格式 YYYY-MM-DD）
- 收入/支出 单选切换（影响分类下拉选项）
- 分类下拉框（根据类型动态切换：收入分类 / 支出分类）
- 金额输入框（数字校验，最多两位小数）
- 备注输入框（可选）
- 保存按钮

交互:
- 切换收入/支出时，分类下拉自动更新
- 保存前执行 models.py 的 validate() 校验
- 保存成功后清空表单，显示成功提示
- 保存失败显示错误信息

#### 2. 收支流水

查看和删除历史记录。

组件:
- Treeview 表格，列: 编号 | 日期 | 类型 | 分类 | 金额 | 备注
- 收入行绿色、支出行红色（视觉区分）
- 顶部统计栏: 收入合计 / 支出合计 / 结余
- 底部删除按钮（选中行后可用）

交互:
- 启动时加载全部数据
- 删除前弹出确认对话框
- 删除后自动备份并刷新表格

#### 3. 月度统计

按月查看收支汇总。

组件:
- 年月选择器（年份下拉 + 月份下拉）
- 查询按钮
- 分类汇总表格（收入分类 + 金额、支出分类 + 金额）
- 合计卡片（收入合计 / 支出合计 / 月度结余）

交互:
- 默认显示当前月份
- 切换年月后点击查询刷新

#### 4. 设置

主题与字体定制。

组件:
- 主题下拉框（ttkbootstrap 内置主题列表）
- 字体族下拉框（系统可用字体列表）
- 字号调节（滑块或数字输入，范围 10-24）
- 预览区域（实时展示当前设置效果的示例文字）
- 应用按钮（保存设置并立即生效）

交互:
- 修改后点击应用，立即更新全局样式
- 设置持久化到 config 或单独的 settings 文件

## 样式定制系统

所有视觉参数集中在 `theme.py`：

```python
# 字体
FONT_FAMILY = "Microsoft YaHei"
FONT_SIZE_TITLE = 18
FONT_SIZE_BODY = 12
FONT_SIZE_SMALL = 10

# 颜色
COLOR_PRIMARY = "#2563EB"
COLOR_SUCCESS = "#16A34A"   # 收入
COLOR_DANGER = "#DC2626"    # 支出
COLOR_BG = "#F8FAFC"

# ttkbootstrap 主题
THEME_NAME = "cosmo"
```

运行时通过 ttkbootstrap 的 Style 对象注入配置。用户在"设置"页修改后，实时更新 theme.py 对应值并刷新全局样式。

## 工程思维要点

1. **GUI 与业务逻辑分离** — gui.py 只负责界面渲染和事件分发，不包含业务逻辑
2. **组件复用** — ui_components.py 中的组件可被多个标签页复用
3. **样式集中管理** — theme.py 一处配置，全局生效
4. **数据层零改动** — models/storage/utils 完全不变，GUI 和 CLI 共享同一套后端
